5 Ways I Improved the mobile experience + a bonus prototype for the future

  1. Defining a tactical approach

We approached this work with the goal to help users stay focused on their edit. By creating a set of guiding principles (which you can read more about), the product manager, engineers, and I had a set of tools for evaluating product decisions that impacted the direction of the editing tool.

  1. Improving perceived performance

Problem: the editor feels slow to load

Solution: a smoother transition between reading and editing

From a white screen with a subtle throbber to a fully animated transition.

Image by Jess Klein /Wikimedia Foundation, CC BY-SA 3.0.

  1. Streamlining in-article wayfinding through section editing

Problem: it’s hard to find what you want to edit

Solution: remove all distracting text to allow for editing of this section

Click the pencil icon and get to just that specific section within the mobile editing mode.

Image by Jess Klein /Wikimedia Foundation, CC BY-SA 3.0.

  1. Unifying the toolbar interface

Problem: contributors can’t find the tools they need when they need them

Solution: a single toolbar with all tools visible

Stop the flickering!!!! We improved the interface by creating a single-state toolbar.

Image by Jess Klein /Wikimedia Foundation, CC BY-SA 3.0.

  1. Contextualized edit cards

Problem: the editor feels cramped

Solution: create more space by changing how and where edit actions are shown.

This gives us flexibility to incorporate more templated card types using this new type of pattern.

Edit templates allow us to facilitate a smoother edit experience.

Image by Jess Klein /Wikimedia Foundation, CC BY-SA 3.0.

BONUS: Prototyping experimental future features

Opportunity: a mobile device has unique capabilities that only can be done on mobile

Solution: a prototype that utilizes a scanner on a phone to detect the ISBN barcode and translate that into a citation.

Impact

At the start of the project, we set a goal of increasing the likelihood contributors will complete the edits they start by 10%. At the end of the project, our analysis showed the interventions we deployed increased this likelihood by 78%.

  • Peter Pelberg, Product Manager
